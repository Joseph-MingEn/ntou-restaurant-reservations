# 2. 規格

| 餐期 | 營業時間 | 可入座時間 |
| --- | --- | --- |
| 午餐 | 11:30–14:30 | 11:30、12:00、12:30 |
| 晚餐 | 17:00–20:00 | 17:00、17:30、18:00 |

- 以 Asia/Taipei 判斷日期與時間。當前時間達到入座前 30 分鐘即截止，含剛好 30 分鐘。每筆佔用區間是入座時間至兩小時後，結束時刻可以交給下一筆。可用桌子必須在整段期間皆空閒。沒有提早離席釋位流程。
- 每組 1 至 4 人。兩人桌六張、四人桌六張。較小團體優先分配兩人桌；同桌型按桌號分配。所有午餐入座選項會互相重疊，晚餐亦同。
- 預約包含日期、入座時間、人數、姓名與電話或 Email。聯絡方式支援 8–15 碼電話（可含常見分隔符）或 Email。成功時回覆訂位編號、桌號和用餐時間。取消會立即釋出桌位，可用原本的 LINE 帳號或業主頁取消。
- 「尚可接待」是空桌的總座位，「最大單組」是空桌中最大桌型。「已訂人數」和「訂位組數」按整個餐期統計，取消的訂位排除。業主可以按日期、餐期與入座時間查看，名單附聯絡方式。
- LINE 私聊指令包含查詢、訂位、取消與定位。定位必須先選擇本人仍有效且尚未用餐結束的訂位。定位邀請 10 分鐘內有效、使用一次。經緯度只有業主查詢介面會顯示，客人可略過。
- Webhook 驗證 LINE 原始請求簽章，並依事件 ID 避免重試造成重複寫入。業主 API 需帶管理金鑰。展示以同瀏覽器共享的示例資料操作，正式以單一 Node 服務的持久化資料為準。

- 客人能查本人有效訂位。改期可改日期、時間與人數，原入座與新入座都須尚未截止。新桌確認前保留原桌，新桌成功後沿用原訂位編號並移除先前分享的定位。
- 業主可在入座前 30 分鐘至用餐結束前記錄報到，也可從入座時間起記錄未到。未到釋出桌位並從備餐量扣除，已報到仍計在當餐備餐量。已取消和未到留在名單供業主查看。
- 網頁顯示指定入座時間「已截止」時，當下可接待人數顯示為零，桌況仍保留實際空桌張數供業主使用。
