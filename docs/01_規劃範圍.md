# 1. 規劃範圍

單店中小型餐廳，6 張四人桌與 6 張兩人桌，總計 12 桌、36 個座位。客人使用 LINE 查詢與訂位，必要時主動分享定位。業主用網頁查看訂位名單、備餐人數和可接桌位。交付 GitHub Pages 靜態展示與可接 LINE Messaging API 的 Node 服務。

## 需求盤點

依 [mattpocock/skills 的 grill-me](https://github.com/mattpocock/skills/tree/main/skills/productivity/grill-me) 逐層盤點。依使用者全程委託的要求，以專案決策回答。

| 問題 | 決策 |
| --- | --- |
| 三小時是營業區間，還是每組的用餐時間？ | 午餐與晚餐營業區間各三小時，每組用餐最多兩小時。 |
| 什麼時候能入座及最晚何時訂位？ | 每 30 分鐘一個入座選項，關店前可用滿兩小時。各入座時間提前 30 分鐘截止。 |
| 如何算「還有幾人」？ | 顯示該入座時段的空桌總座位、最大單組人數，以及兩種空桌的張數。已分配的桌子由該組獨占。 |
| 兩種桌型如何配桌？ | 每組 1–4 人，使用最小合適空桌。現場併桌條件未知，初版採固定單桌。 |
| LINE 定位如何連到預約？ | 在私聊輸入訂位編號選取自己的預約，10 分鐘內主動分享定位。 |
| 業主要備多少？ | 以午餐或晚餐加總確認中的訂位人數，並列出分時到店人數與查詢時間的空桌。 |

本版範圍以預約、查詢、取消、定位和備餐為主。付款、候位、跨店、多組共桌及自動安排定位推播留待另案。
