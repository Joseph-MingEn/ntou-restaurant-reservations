# 3. 實作計畫

1. 以共享預約模組統一計算時段、配桌、剩位和備餐總量。
2. 透過 LINE 對話命令接起查詢、訂位、取消與定位。為真實 Webhook 加入簽章驗證、事件重送和持久儲存。
3. 做出 GitHub Pages 櫃台展示。用 LINE 模擬對話驗證客人流程，業主畫面提供餐期、空桌配置及分時文字名單和圖像動畫。
4. 根據 [mattpocock/skills 的 tdd](https://github.com/mattpocock/skills/tree/main/skills/engineering/tdd) 逐個切片立測試、觀察失敗、實作，再執行全套。測試介面為預約模組、LINE 訊息處理及 HTTP API，瀏覽器另外驗證畫面和切換。
5. 將靜態資料夾與正式服務分開。發佈後驗證 Pages 網址，線上 LINE 驗證需管理權限和 HTTPS 服務。

以共用桌位規則產生可選時段，接入 LINE 日期事件和網頁模擬。保留單行訂位指令。

以台灣時間解析常用相對日期、中文時刻和人數，接回既有桌位檢查與訂位規則。

Gmail 提醒由正式 Node 服務每分鐘掃描。沿用台灣時間與訂位狀態，將寄送紀錄和預約資料一同持久保存。發信端使用 Gmail API 的寄信權限，LINE 回覆在已啟用 Gmail 時補上提醒說明。

建立共用餐廳地點設定，供 LINE、網頁展示與 Gmail 提醒讀取。
