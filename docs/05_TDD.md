# 5. TDD 紀錄

逐步先執行新增測試，確認失敗後補齊行為，再重跑。

| 切片 | 首次失敗 | 通過結果 |
| --- | --- | --- |
| 兩小時桌位重疊 | 預約模組尚未建立 | 11:30 和 12:30 分配不同桌，整段衝突統計正確 |
| 取消與業主備餐 | 缺少取消及餐期統計 | 他人不能取消，取消後餐期人數及桌況更新 |
| LINE 建立預約 | 未有 LINE 對話入口 | LINE 訂位回覆編號，業主讀到同一筆 |
| 位置分享 | 未有定位選取流程 | 驗證帳號、確認 10 分鐘時限，過期或重複分享會拒絕 |
| 查本人訂位與改期 | 缺少查詢與改期命令 | 改期失敗保留原桌，成功沿用編號 |
| 報到與未到 | 缺少報到狀態 | 報到計入備餐，未到釋位 |
| 大組相鄰併桌 | 五人被舊上限拒絕，分散空桌未檢查 | 五人分配兩張相鄰桌，空桌碎片不接受五人 |
| Webhook 和業主 API | 未有 HTTP 服務 | 驗證簽章、業主認證、重送去重和服務重啟 |

完整套件另驗證截止時間邊界、四人桌額滿、多人同時搶桌、日期與聯絡資料。執行方式為 `npm test`。

公開頁面驗收時，瀏覽器可同時快取舊 JavaScript 與新 HTML，使人數選單空白。已替頁面與匯入模組加上相同版本的資源網址。GitHub Pages 和 Node 伺服器皆支援附版本的靜態資源路徑。

新增日期選擇事件、已截止時段隱藏、客人各自的選擇狀態和確認時重新檢查桌況的測試。
